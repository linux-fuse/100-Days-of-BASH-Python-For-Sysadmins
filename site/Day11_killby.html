Day 11 - Auto-Restart a Failed Service

Purpose:

This script automatically checks whether a given systemd service (like nginx, sshd, or mysql) has failed.
If it detects a failure, it restarts the service automatically.
This helps maintain system uptime without manual intervention.

Bash

#!/usr/bin/env bash
# Script to check if a service has failed and restart it if needed.

# Default service to check is 'nginx' unless specified as the first argument.
SVC=${1:-nginx}

# Check if the service is failed using systemctl.
# The --quiet flag suppresses output; exit code determines result.
if systemctl is-failed --quiet "$SVC"; then
  echo "$SVC failed — restarting"
  
  # Restart the service if failed
  systemctl restart "$SVC"
else
  echo "$SVC OK"
fi
systemctl is-failed exits with 0 when the service is failed, which is the opposite of many commands where 0 means success — so the logic uses that to trigger a restart.

Python 3


          #!/usr/bin/env python3
import subprocess
import sys

# Get the service name from command-line argument or default to 'nginx'
svc = sys.argv[1] if len(sys.argv) > 1 else 'nginx'

# Run 'systemctl is-failed' and capture its output
# The command returns exit code 0 if the service has failed
s = subprocess.run(['systemctl', 'is-failed', svc],
                   capture_output=True, text=True)

# Check the exit code
if s.returncode == 0:
    # If return code is 0, service is failed
    print(f"{svc} failed — restarting")
    # Restart the service
    subprocess.run(['systemctl', 'restart', svc])
else:
    # Any other return code means OK, inactive, or another state
    print(f"{svc} status OK or not failed")

Explanation:

  1. Both scripts check the status of a given systemd-managed service.

  2. If the service is in a failed state, they automatically restart it.

  3. If it’s healthy, they simply report “OK.”

  4. This can be added to a cron job or systemd timer for automated uptime recovery.

  5. The script first checks the service state using systemctl is-active.

  6. If it’s active, it simply prints confirmation.

  7. If not, it attempts to start the service.

  8. After starting, it verifies the operation succeeded.

  9. Works well as a cron job, monitoring hook, or daily service watchdog.
