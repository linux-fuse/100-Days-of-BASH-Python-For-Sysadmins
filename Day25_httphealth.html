Day 25 - Web Server Health Check

Script #25 introduces a simple HTTP health checker, implemented in both Bash and Python, allowing automated uptime checks or integration into CI/CD monitoring pipelines.

Bash


#!/usr/bin/env bash

# URL to check
URL=${1:-http://localhost:80/}

# Check URL
if curl -sf "$URL" >/dev/null; then
    echo "OK"
else
    echo "FAIL"
    exit 1
fi

Explanation:

 

  • URL=${1:-http://localhost:80/} – Uses a provided URL or defaults to localhost.

  • curl -sf "$URL" –

    • -s hides output (silent mode)

    • -f treats HTTP 4xx/5xx responses as failures

  • >/dev/null – Discards the content, checking only the status.

  • if ... then ... else – Prints "OK" for success, "FAIL" otherwise.

  • exit 1 – Returns a nonzero exit code on failure, ideal for monitoring tools or scripts.

 

Python 3


#!/usr/bin/env python3
import sys, requests
# URL to check
url = sys.argv[1] if len(sys.argv) > 1 else 'http://localhost:80/'

# Check URL
try:
    #Send request
    r = requests.get(url, timeout=5)
    print(f"HTTP {r.status_code}")

    #Check response
    if r.status_code == 200:
        print("OK")
    else:
        print("FAIL")
        sys.exit(1)
except requests.exceptions.ConnectionError:
    print("FAIL: unable to connect to host")
    sys.exit(2)
except requests.exceptions.Timeout:
    print("FAIL: Request timed out")
    sys.exit(3)
except Exception as e:
    print(f"FAIL: Unexpected Error {e}")
    sys.exit(4)

Explanation:

 

  • requests.get(url, timeout=5) — Attempts to fetch the page with a 5-second timeout.

  • Checks r.status_code:

    • 200 means OK

    • Other codes (404, 500, etc.) count as failures

  • Handles specific exceptions for connection, timeout, and generic errors.

  • Prints messages and uses appropriate exit codes for integration with automation pipelines.
